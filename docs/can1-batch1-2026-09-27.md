## 厂商协议核对

依据：`ZDT_X42S第二代闭环步进电机使用说明书V1.0.2_251118.pdf`。以下全为 CAN 数据字节，不含串口协议中的地址。扩展数据帧，ID=`(motor_id << 8) | packet_index`。本批均能容纳于一个 CAN 帧，packet=0，ID1 为 `0x100`，固定校验 `6B`。

| 功能 | CAN 请求 | CAN 回复 | 依据 |
| --- | --- | --- | --- |
| F6 EMM 速度 | `F6 dir rpm_hi rpm_lo acc sync 6B`，DLC=7 | `F6 02/E2/EE 6B`，DLC=3 | p51 |
| 35 真实速度 | `35 6B`，DLC=2 | `35 sign rpm_hi rpm_lo 6B`，DLC=5 | p67 |
| 3A 状态 | `3A 6B`，DLC=2 | `3A flags 6B`，DLC=3 | p69–70 |
| 1A 固件/选项 | `1A 6B`，DLC=2 | `1A flags 6B`，DLC=3 | p73 |
| FE 立即停止 | `FE 98 00 6B`，DLC=4 | `FE 02/E2/EE 6B`，DLC=3 | p56 |

F6 的方向 0=CW、1=CCW；acc=0 表示直接按给定速度运行，sync=0 表示立即执行。本批不发送同步缓存或广播动作。返回 `02` 只说明命令正确，`E2` 是参数/条件错误，`EE` 是格式错误。3A的bit0仅作STATUS_ENABLE_BIT诊断，不作为运行门禁；堵转保护bit3仍阻止运行。CAN1不发送F3使能/失能帧。

EMM 的 F6 默认单位是 1 RPM。`S_Vel_IS` 开启时，F6 下发值按 10 倍编码；通过 1A bit7 自动读取，bit1 必须确认 EMM。**EMM 的 35 反馈始终按 RPM 解码，不受 `S_Vel_IS` 影响。** X 固件的 35 才需要除以 10（p67）。本批不支持 X 的运行；`PROTO X` 会取消运动并拒绝切换，不能用它绕过单位检查。

运行 60 RPM 时，CMD_SCALE10=0 编码 `003C`，CMD_SCALE10=1 编码 `0258`；真实 35 预期约 `003C`，符号位独立。速度是否与真实转速、方向相符，需要台架观察。1A 本批严格按 p73 单状态字节格式接收；该页同时提及 bit8–9 扩展锁定等级，却未清楚给出扩展返回布局。如实际 RX_REJECT 增长且 OPTION_REPLY=0，应捕获 1A 原始帧核实，不能猜字节序或强行放行非零速度。

本地 HAL 的 `HAL_CAN_AddTxMessage` 即使 DLC 小于 8，仍读取完整 8 字节。本驱动先复制到零填充的 8 字节缓冲，再保持真实 DLC 提交；主机测试模拟同样的读取行为。HAL 立即复制到硬件邮箱，函数返回后不持有栈缓冲。

## 发送、反馈与停车语义

只有一个在途硬件帧；没有软件命令 FIFO、恢复门禁或重启控制器状态机。普通速度/手动查询直接尝试 HAL 提交，忙则明确返回 BUSY，不隐式排队或自动重发非零速度。主循环按名义周期安排查询：35为20ms，3A为100ms，1A为1000ms；慢发送时实际周期变长，到期速度查询与其他到期请求交替，不挤掉停车请求。未得到速度回复的查询等待20ms，下一次周期继续查询。

| 返回值 | 意义 |
| --- | --- |
| 0 | 速度/查询：HAL 已接受；STOP：安全待办已接受。均不代表已发送或已执行 |
| 1 | BUSY，未提交；显式命令需要主机再发 |
| 2 | HAL 提交失败 |
| 3 | ID、数值或掩码非法 |
| 4 | 当前阶段不可用/未就绪；ID2–4、整车操作或初始化失败 |

`SUBMITTED` 在 HAL 接受时增长；`TX_DONE` 仅在实际 TXOK 回调消费时增长；仲裁失败/TERR/abort/提交失败分别进入失败诊断。TXOK 不能证明目标电机收到命令，因为其他 CAN 节点也可能提供总线 ACK。`SPEED_REPLY`/SEQ/VALID/tick 只在主循环消费严格合法的新 35 回复时更新，时间戳取接收中断时刻。ACK、3A、1A、发送完成和 Bus-Off 退出都不刷新速度年龄。

中断每类只保存最新一份原始数据；覆盖计数明确记录，被覆盖的速度样本不虚增 SEQ 或零速次数。NACK 单独锁存，后续 ACK 覆盖原始槽也不能掩盖拒绝动作。中断不 printf，不执行运动业务或控制器恢复。

STOP 立即清除目标 RPM，并请求 FE + F6 零速；若非零 F6 在途，异步请求撤销。已上总线的旧帧可能赢得撤销竞争，因此后续仍发送安全停车命令。STOP 分成：

1. REQUEST：取消旧目标、接受安全待办。
2. SENT：本轮 FE 和 F6 零速都取得 TXOK。
3. ZERO_CONFIRMED：在最后一个停车帧 TXOK 后收到两份新的、准确解码为 0 RPM 的 35 回复，且仍保持新鲜。

不能用请求前缓存、ACK 或发送完成代替真实零速确认。尚未确认或重新断流时，安全停车节流重发，未成功的 FE/F6 交替尝试，失败后至少等 100 ms，并保留速度查询机会。成功 FE 后可继续发送 F6。无回复时也不能假确认停车。

`MOTOR STOP ALL` 仍为四轮请求，因此本批返回 4，同时对 ID1 请求安全停车；它不宣称另外三个电机已停。默认四轮 `MOTOR STOP STATUS` 仍会显示 UNCONFIRMED，另有 `MOTOR SINGLE STOP` 行显示 ID1 的真实过程。这是阶段范围的结果，不是伪造四轮就绪。

## 故障处理与诊断

单电机非零速度需要合法EMM选项、新鲜3A状态、无堵转保护、健康的控制器、60 ms 内的速度反馈，以及此前停车确认。60 ms 为本批台架运行限制；通用反馈 300 ms、停车 600 ms 未放宽。诊断 VALID 表示曾收到有效数据，新鲜度需要 AGE 和就绪条件共同判断。

速度断流、迟到/失败的运动 TX、NACK、状态异常、error-warning/passive/Bus-Off 都撤销非零目标。缺失区间后首个新回复不能掩盖此前断流，即使主循环曾暂停。反馈恢复和 ABOM 退出不会恢复旧 RPM；必须重新提交新的显式运行命令。

保持生成配置中的硬件自动重传和 ABOM。单帧在途超过 50 ms 请求一次异步 abort；超过观察期限未完成则记录 ABORT_STUCK，不冒充邮箱空闲，不连续 abort，也不 Stop/Start/Init。`SW_RESTART` 本批固定为 0。Bus-Off 进入/退出通过 ESR 和错误中断证据计数；ABOM_EXIT 仅表明 BOFF 清除，不代表通信持续稳定。

本地 HAL 清 TX RQCP 后，TERR/ALST 进入 ErrorCallback 而不是 abort 回调，驱动正确消费这一结果。错误回调保存 HAL_ERR_LATCH 后只清 HAL 软件累计错误字段，以便后续统计新错误，不清硬件故障或重启外设。不启用 LAST_ERROR_CODE 中断，因为本地 HAL 会在回调前清 ESR.LEC；保留 warning/passive/BOFF/error 中断，主循环直接读 LEC。LEC 是最后错误记录，不能当作本次采样新发生的错误。

`CAN STATUS` / `CAN MONITOR ON` 每秒日志包括：

- STARTED：控制器/过滤器/通知初始化成功；LINK_READY：ID1 通信条件满足；RUN_READY：单电机运行条件满足；CHASSIS_READY 恒为 0。
- REQUEST：帧提交尝试次数；SUBMITTED/TX_DONE/TX_FAILED/BUSY/REJECTED 分开。
- RX/SPEED_REPLY/STATUS_REPLY/OPTION_REPLY/ACK/NACK，覆盖、拒绝、FIFO overrun、查询超时。
- ID1–4 的 VALID/RPM/AGE_MS/SEQ。ID2–4 未实现，VALID=0、SEQ=0、AGE_MS=4294967295 表示无有效样本，不是开机到现在的伪年龄。
- AGE_AVG_MS 为有反馈后主循环至少间隔 1 ms 的采样算术均值，AGE_N 是采样数，循环延迟会影响采样分布；AGE_MAX_MS 还包含已知完整反馈间隔，不能只看快照低 AGE。
- INTERVAL_AVG/MAX 是消费到的新速度帧的接收时间间隔；RTT_AVG/MAX 是单个待查询从 HAL 提交到接收回复的估计延迟。协议没有事务号，迟到/主动推送的同类回复不能严格逐请求唯一匹配，应结合原始总线帧解释。
- GAP_MS：本轮 AGE 大于名义 20 ms 时的连续无新速度反馈时间；GAP_MAX_MS 为最大已观测无反馈间隔，保留断流后的历史值。未有首个样本时用 VALID=0 判定，不把无样本打印为正常 GAP。
- 停车待办/SENT/ZERO_CONFIRMED、目标 RPM、TX_TIMEOUT/ABORT/ABORT_STUCK/CANCEL、故障原因与 BOFF_ENTER/ABOM_EXIT/SW_RESTART。
- ESR/TEC/REC/LEC/EWGF/EPVF/BOFF/峰值、HAL_ERR_LATCH、MCR/BTR，以及 ABOM/AUTO_RETRANS 实际位。

原因编号：0=无，1=发送失败，2=发送超时，3=速度反馈断流，4=错误 warning/passive，5=Bus-Off，6=电机 NACK，7=状态/选项/就绪异常，8=初始化失败。INIT_ERR：1=过滤器，2=Start，3=通知。

## 烧录验证步骤（待用户执行）

先只连接地址 1 的电机，使用台架/悬空轮验证。确认电机为 EMM、500 kbit/s、固定 6B；若需要观察控制 ACK，Response 用 Receive 或 Both。软件不会修改这些菜单。使用上述 ELF 或 HEX；若用 CubeIDE 工程重新构建，先刷新工程并 Clean Build，避免烧录旧 Debug 目录产物。

USART1：115200 baud，文本命令逐行发送。每次 MCU 复位后重新发送监视命令并保存日志，因为主机监视开关不会跨复位保留。

```text
CAN STATUS
CAN MONITOR ON
HOST LINK COM
MOTOR FEEDBACK
MOTOR STOP STATUS
CAN STATUS
```

先观察至少 30 秒：SUBMITTED/TX_DONE/RX/SPEED_REPLY/ID1 SEQ 持续增长；AGE 反复回落，记录 AGE_AVG/MAX、INTERVAL_AVG/MAX、RTT_AVG/MAX、GAP/MAX；OPTIONS_VALID=1、EMM=1，CMD_SCALE10 与菜单一致；3A的STATUS_ENABLE_BIT仅作原始状态诊断；ABOM=1、AUTO_RETRANS=1、无 BOFF。若显式命令返回 1，表示这次未提交，稍后重发，不能把它视为动作已完成。

LINK_READY=1、ZERO_CONFIRMED=1、RUN_READY=1，才进行短时低速方向/单位验证，逐条等待停止确认：

```text
MOTOR RUN 1 60 1000
MOTOR FEEDBACK
MOTOR STOP 1
MOTOR STOP STATUS
MOTOR RUN 1 -60 1000
MOTOR STOP 1
MOTOR ZERO 1
MOTOR STOP STATUS
```

检查真实回复约 +60/-60 RPM，物理转动方向符合 CW/CCW；ZERO_CONFIRMED 只能在新 0 RPM 回复后出现，1 RPM 也不会算准确零速。验证限时自动停车。收到 STOP 或异常后，即使 SEQ 恢复增长，TARGET_RPM 必须为 0，不得重新出现旧非零目标。

| 场景 | 本批实测内容 |
| --- | --- |
| 冷启动/重新上电 | 首个有效反馈时间、持续 30 秒指标；不能靠启动延时伪造成功 |
| 开发板复位，电机不断电 | 旧运行取消，新启动 FE/F6 零速，重新取得反馈并持续增长 |
| 重新烧录，电机不断电 | 与复位相同；记录固件 SHA，确认烧录的是本批产物 |
| 电机先上电/后上电 | 无电机时不得 VALID/零速确认；上电后停车待办和查询持续，取得真实回复 |
| 短暂断流再恢复 | AGE/GAP 增长、取消原因/次数、反馈恢复、目标保持 0；不要求 SW_RESTART 增长 |
| STOP 与在途速度/重复 STOP | 不重发旧速度，分别观察提交、TX_DONE、真实两份零速 |
| CAN2/OPS9/串口 | `G6220 STATUS` 的真实 RX/AGE、`OPS STATUS`/`OPS MONITOR ON`、`PING` 和命令回复继续正常 |
| 四电机 | 本批不放行、不声称验证；单电机实测通过后进入第二批 |

总线完全不可达时，软件只能取消目标并保留安全发送请求，无法保证远端立即物理停转。说明书 p85–86 的驱动器心跳保护默认 0（未启用），本批不写此设置；第二批接整车前须核实并验证驱动器自身通信超时保护。不要把 MCU 看门狗复位等同于外置电机已停。

若复现 TX_DONE/RX/SEQ 固定，保留事件前后连续 CAN MONITOR、CONTROL STATUS、G6220 STATUS 和 OPS STATUS 日志，明确实际接入电机、供电顺序、复位/烧录/断流时刻。先用 TX 提交/完成与原始回复、MCR/ESR 分层定位；本批不会打印未经持续验证的 CAN RECOVERED，也不会扩大超时掩盖断流。收到实测证据后再决定是否需要配置变更或软件恢复，并按照用户要求对生成配置变更单独说明、等待明确指示。
