## 项目目的

这是基于 STM32F407VET6 的四轮麦克纳姆物流小车底层控制工程。STM32 负责四轮电机控制、OPS9 位姿采集、X/Y/YAW PID 闭环、速度规划和安全停车。电脑用于调试、串口监视与 PID 调参；树莓派用于自主任务、导航和提交位姿目标。

整车控制链是：主机提交目标 → OPS9 位姿反馈 → X/Y/YAW PID 与速度规划 → 麦克纳姆运动学逆解 → 四轮电机执行。CAN1 必须可靠发送速度和停止命令，并持续取得真实电机反馈。

第一目标是通信成功并持续稳定，特别是单片机复位、重新烧录和重新上电后能重新通信。先完成单电机最小通信，再扩展至四轮，最后接回整车控制。不要先叠加复杂队列和恢复门禁，也不要通过扩大超时掩盖断流。

## 工程与硬件

- 工程：`C:\Users\steph\STM32CubeIDE\workspace_1.19.0\serialPlotTest`。
- 主控：STM32F407VET6；SYSCLK 168 MHz，CAN 所在 APB1 42 MHz。

- CAN1：现有500 kbit/s，PB8 RX、PB9 TX，扩展帧；旧协议地址形式为 `(motor_id << 8) | packet_index`，需核实实际厂商协议。

- CAN2：DM-G6220 云台，1 Mbit/s 标准帧，PB12 RX、PB13 TX；必须保留。
- OPS9：USART2，PA2 TX、PA3 RX；PC/树莓派链路：USART1，115200 baud。
- 车体+X向右、+Y向前；位置mm，航向degree，线速度m/s，角速度rad/s，电机转速RPM。
- 轮径75 mm，轮距229 mm，轴距255 mm。

## 历史问题

旧实现出现 CAN READY=0、AGE_MS持续增长、复位后无法恢复，以及反复打印 `# CAN RECOVERED MOTION=STOPPED MASK=0x0F`。曾经 AGE_MS 能回到约20ms，但复位后的稳定性不足。

最近日志：TX_OK/RX长时间固定548，四轮SEQ不变、反馈年龄增长至约30秒；修复计数增加却没有新反馈。随后短暂恢复至 TX_OK/RX=630、四轮SEQ增长、RECOVERIES从3至4。最后成功发送51394ms，故障51896ms，间隔502ms，又进入停滞。ESR出现EPVF=1、EWGF=1、TEC从129至199、LEC=4、BOFF=0。

旧逻辑每500ms没有发送进展就停启控制器，恢复判据允许错误被动状态，只确认恢复瞬间四轮反馈新鲜。RECOVERED并不证明持续稳定。这些数据不能唯一判定底层根因。历史文档只能提供线索，不能视为当前实现。

开发板此前的异常红灯问题已由我修复。CAN故障请优先审查软件，但时序和总线判断仍需实际证据。

## 实现要求

1. **不要修改 `.ioc` 及相关生成配置文件。** 在电机驱动与应用接入层实现；如证明配置必须调整，先说明证据和具体改动，等待我的明确指示。
2. 保留 CAN2、OPS9、串口与 PID。CAN2依赖CAN1共享时钟及过滤器资源，不能破坏它们。
3. 结构简单、非阻塞：初始化一次；主循环安排发送/查询；接收中断只做有界收取与必要记录；应用消费反馈。明确区分请求提交、发送完成、电机回复和业务就绪。
4. 第一批打通单电机最小收发、零速与真实速度反馈，核实F6/35/3A格式、应答和速度缩放。电机上电即使能，不发送F3使能/失能请求。第二批扩展四轮并接回运动、停车、诊断及必要恢复。每批完成后编译测试，由我烧录验证是否复现。
5. AGE_MS、SEQ、VALID只能由真正有效的新速度反馈更新。发送完成、重启控制器或普通ACK不能刷新速度反馈年龄。
6. 争取四轮反馈年龄达到约20ms量级，结合实际请求/回复延迟评估频率；报告平均值、最大值和连续断流时间。不能只放宽超时让READY=1。
7. 故障或复位后禁止恢复旧运动目标。STOP取消旧目标，明确区分提交、发送完成与真实零速确认。通信未实现或失败时不能报告成功。
8. 恢复必须有证据与节流，避免每循环复位、启停或密集重试；先验证自动重传和Bus-Off管理，再决定软件恢复方式。
9. 保留简洁诊断：请求/提交/发送完成/失败计数、有效速度回复、每轮AGE/SEQ、TEC/REC/LEC/BOFF、恢复原因和次数；中断中禁止printf。
10. 不要把模拟测试当实车验证。交付时说明流程、文件改动、测试证据、待烧录验证项及产物路径。
